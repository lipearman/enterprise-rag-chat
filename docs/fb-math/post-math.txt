🧮 หลังจากกด “ส่งคำถาม” ระบบ RAG ทำอะไรบ้าง: มองผ่านคณิตศาสตร์ล้วน ๆ

โพสต์ที่แล้วเล่าเรื่องการสร้างระบบไปแล้ว รอบนี้ขอเจาะเฉพาะช่วงเวลาไม่กี่วินาทีหลังผู้ใช้กดส่ง ว่าเกิดอะไรขึ้นบ้างในเชิงคณิตศาสตร์ ทุกสูตรเขียนตรงกับโค้ดจริงของระบบครับ 👇

[รูป 0] ภาพรวม
ทั้ง pipeline เขียนเป็นการประกอบฟังก์ชันได้ว่า
a = LLM( S ⊕ C( R(f(q)) ∪ F(I(q)) ), q )

[รูป 1] Intent Router: I(q)
เป็น decision list ตรวจ keyword 30 คำตามลำดับ staff → fact → claim → knowledge ความซับซ้อน O(|K|·|q|) ไม่ต้องเรียก AI เลย

[รูป 2] Embedding: f : Σ* → ℝ¹⁰²⁴
คำถามถูกแปลงเป็นเวกเตอร์ 1,024 มิติ ถ้าโมเดลคืน NaN จะหั่นข้อความเป็นช่วงละ 150 ตัวอักษร เฉลี่ยเวกเตอร์ที่ใช้ได้ แล้ว L2-normalize ให้กลับมาอยู่บน hypersphere หนึ่งหน่วย

[รูป 3] Cosine similarity
sim = q·d / (‖q‖‖d‖) วัดมุมระหว่างเวกเตอร์ ไม่สนความยาว ตัวอย่าง 3 มิติ: คะแนน 0.96 (16°) และ 0.48 (61°) ผ่านเกณฑ์ ส่วน 0.17 (80°) ถูกตัดทิ้ง

[รูป 4] IVFFlat: Approximate Nearest Neighbor
ใช้ k-means แบ่งเวกเตอร์เป็น 100 กลุ่ม ตอนค้นจะเทียบกับ centroid ก่อน แล้วเทียบเฉพาะในกลุ่มที่ใกล้สุด ที่ N = 10,000 ลดจำนวนการคูณจาก 10.24 ล้านเหลือ 204,800 ครั้ง เร็วขึ้นราว 50 เท่า แลกกับ recall ที่อาจลดลงเล็กน้อย

[รูป 5] Top-k + Threshold
R = { d ∈ TopK₆ : sim ≥ 0.40 }
τ = 0.40 เท่ากับกรวยมุม 66.4° รอบเวกเตอร์คำถาม หรือระยะยุคลิด ‖q−d‖² ≤ 1.2

[รูป 6] Hybrid merge + Context
ผลจาก SQL (σ ในพีชคณิตเชิงสัมพันธ์) ต่อด้วยผลจากเวกเตอร์ ตัดเอกสารชิ้นละ 600 ตัวอักษร ส่วนเอกสารจึงยาวไม่เกิน 3,606 ตัวอักษร (ตัวเลือก) reranker จัดลำดับใหม่ด้วย argsort ของคะแนนที่ LLM ให้

[รูป 7] LLM Generation
P(a|x) = Π P(aₜ | a₍<ₜ₎, x) สร้างคำตอบทีละ token ผ่าน self-attention softmax(QKᵀ/√dₖ)V และสุ่มจาก softmax(z/T) ขั้นที่ต้องการผลเดิมทุกครั้งตั้ง T = 0 (greedy)

[รูป 8] Sources + Grounding
แหล่งอ้างอิงคือ URL ไม่ซ้ำ เรียงตาม sim เหลือ 5 อันดับ แสดงเป็น % (0.781 → 78%) และ (ตัวเลือก) ให้ LLM ประเมิน g(a, C) ∈ {0,1} ถ้าคำตอบไม่มีหลักฐานรองรับ จะแทนด้วยคำตอบที่แก้แล้ว

สรุปในบรรทัดเดียว
q → intent → q ∈ ℝ¹⁰²⁴ → R₆,₀.₄ → C → a → a_final
